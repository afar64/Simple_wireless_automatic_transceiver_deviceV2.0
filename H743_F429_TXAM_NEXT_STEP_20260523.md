# H743/F429 TXAM Next Step

## Current state

Current `WIRELESS` project is still in the last verified bridge state:

- `H743` local `CH0` can be set as LO.
- `H743 USART3` can send WinnerI text commands to `F429 UART4`.
- `F429` executes those commands and returns text responses.
- The existing bridge implementation is still **startup-driven**, not CLI-driven.

Current bridge source files:

- `Core/APP/WinnerBridge/app_winner_bridge.h`
- `Core/APP/WinnerBridge/app_winner_bridge.c`

## Verified chain

Bench-verified chain:

`H743 CH0 LO + H743 USART3 -> F429 UART4 -> FPGA/AD9767 -> LTC5598 -> Tek CH3`

Previously verified command sequence:

```text
QG 1050
QP 0
IO 300
QO 0
TAM 10000 8192 1200 500
```

And local LO:

```text
DDS CH0 FREQ 130000000 AMP 512
```

Measured result on Tek CH3:

- envelope frequency about `10 kHz`
- AM depth about `46.42%`

## What needs to change next

Do not auto-send bridge commands at startup anymore.

Instead, add one integrated CLI command on `USART1`:

```text
TXAM <LO_HZ> <LO_AMP> <QG> <QP> <IO> <QO> <FM> <OFFSET> <AMP> <DEPTH>
```

Example:

```text
TXAM 130000000 512 1050 0 300 0 10000 8192 1200 500
```

Expected behavior:

1. H743 handles local part:
   - set `CH0` frequency
   - set `CH0` amplitude
   - enable `CH0`
2. H743 forwards F429 part over `USART3`:
   - `QG`
   - `QP`
   - `IO`
   - `QO`
   - `TAM`
3. H743 mirrors F429 replies back to `USART1`

- Do not add `TXFM`, `TXASK`, `TXFSK`, `TXPSK` yet.
- Do not connect this to UI yet.
- Keep `DDS?`, `DDS CH0 ...`, `DDS CH1 ...` intact.
